# L3 real-app evaluation (2026-10-24)

Seven open-source Go apps at pinned commits, analyzed with `cango -a 3` via
`scripts/eval_l3.sh`. Host: Apple M3 Max, 16 cores, 64 GB, macOS. Analyzer built with
go1.27.3 (see Finding 2). Every run is `--eager` (no cache). Each app is first run once
and discarded to warm the Go build/module cache, then timed: `-a 2 -j 1`, `-a 3 -j 1`,
`-a 3 -j 16`, and a second `-a 3 -j 16`. Wall time and peak RSS come from `/usr/bin/time -l`.
Counts are from the `-a 3 -j 1` output. "In-project" and "external" split `call_graph` edges
by whether `dst` is an `@external` id.

L3 volume, edge/node-kind breakdowns, cost, output size and consistency checks over these
outputs: [`l3-dataflow-metrics.md`](l3-dataflow-metrics.md).

## Observations

- **Scale:** L3 adds little wall time over L2: +0.0 to +0.8 s on the six smaller apps and
  +10 s on cockroach (23 s to 33 s). Throughput is dominated by loading and type-checking.
  `-j 16` buys up to about 20 percent on `-a 3` (nothing on cobra), not more, because L3 is a small part of total time.
- **Memory:** peak RSS is about 13 GB on cockroach (1.1 GB of JSON) and 4.5 GB on openbao.
  It is dominated by `go/packages` type information, not by L3.
- **-a 3 over -a 2:** the delta is single-digit seconds even at 1.4M body nodes. No app came
  near the 60-minute stop condition; cockroach took 33 s per run.

## Findings

### 1. Non-deterministic `call_graph` for repeated `<pkg>.init` (fixed in `679f995`)

dae and cockroach failed the byte-identical `-j` check. Fixed in `679f995` (Task 12b); the
rerun results are below.

- Not a `-j` problem: three `-j 1` runs of dae also differ from each other, and so do three
  `-a 2` runs. It is run-to-run nondeterminism.
- Scope: everything except `call_graph` is byte-identical across all three runs (checked by
  hashing the JSON with `.application.call_graph` deleted). The `call_graph` edge counts are
  equal; the differing edges are all `src = ...<pkg>.init` edges (dae 4 differing lines,
  cockroach 118 differing lines out of 211,692 edges), where the same `(init, callee)` edge is attributed to a
  different file's `init`.
- Cause (confirmed): `internal/semantic_analysis/call_graph.go` `Build`
  iterates the `symbolTable` map, and dedups edges with `seen[[2]string{callable.Signature,
  calleeSig}]`. `<pkg>.init` is non-unique (one per file; Go allows several `init` per
  package), so the first file visited in random map order wins and the edge's `SourcePath`
  varies.
- The dedup also dropped edges, not only moved them: when two files' inits called the same
  callee, only the first-visited init kept the edge, so the edge counts were equal across runs
  but short.
- Fix (`679f995`): `seen` is keyed on `(callable.Path, callable.Signature, calleeSig)`, so every
  init keeps its own edges, and `Build` walks files, types and callables in sorted key order.
  Regression tests: `internal/syntactic_analysis/v2emit/gate_l2_inits_test.go` over the
  `testdata/dataflow/inits` fixture (two files, each `init()` calling `setup()` and
  `os.Getenv`), asserting each init's edges and 10 byte-identical fresh builds.
- Rerun after the fix (same pinned commits, `--eager`, `-j 16`), with `-a 3 -j 1`, `-a 3 -j 16`
  and a second `-a 3 -j 16`:

  | app | -j identical | call_graph edges before | after | in-project / external after |
  |---|---|---|---|---|
  | dae (GOOS=linux) | yes | 7,975 | 7,985 | 3,230 / 4,755 |
  | cockroach | yes | 211,692 | 212,605 | 156,876 / 55,729 |

  Against the pre-fix output (dae: a fresh `GOOS=linux` run of `fd24bdf`), no edge is removed,
  and every added edge (dae 10, cockroach 913) has an `init` source: the edges the old dedup
  dropped. Everything outside `call_graph` is byte-identical.
- Latent elsewhere: listmonk (25), memos (36), nats-server (8) and openbao (49) have `init`
  edges too and happened to be stable in three runs, so the unit and gate tests would not
  catch this on small fixtures.

### 2. Analyzer must be built with a Go toolchain at least as new as the target's `go` line

Built with go1.26.4, the analyzer type-checked listmonk, memos and openbao (`go 1.27.x`)
with one "package requires newer Go version go1.27 (application built with go1.26)" warning
per package, producing a degraded result with no error exit. The eval binary is built with
`GOTOOLCHAIN=go1.27.3 go build -o /tmp/cango-eval ./cmd/codeanalyzer`. Release packaging
should build with the newest Go toolchain, and the warning is worth surfacing in the docs.

### 3. Neo4j `--eager` push failed on Neo4j 5.x (fixed in `6f250ea`)

Found by the Task 12 live run against Neo4j 5.26. The `--eager` purge
(`internal/neo4j/bolt.go`, `eagerPurgeQuery`) uses `CALL (n) { DETACH DELETE n } IN
TRANSACTIONS OF 5000 ROWS` but ran inside `session.ExecuteWrite`, an explicit transaction.
Neo4j rejects that (`'CALL { ... } IN TRANSACTIONS' can only be executed in an implicit
transaction`), so every `--eager` push onto a database that already held the app failed. Both
`TestIntegration_*` tests (build tag `neo4j_it`) failed on it. Fix (`6f250ea`): the purge runs
as an auto-commit transaction (`session.Run` plus `Consume`). It is the only `IN TRANSACTIONS`
statement; every other write still goes through `ExecuteWrite`. Verified live on Neo4j 5.26:
the full `neo4j_it` suite passes, and two CLI `--eager` pushes of `testdata/dataflow` give the
same `GO_CFG_NEXT` / `GO_CDG` / `GO_DDG` counts, 364 / 224 / 201, equal to the JSON (352 / 219 /
201 before the `inits` fixture was added to it), and a planted stale node under the app prefix is
purged.

## Degraded measurements

### dae: eBPF generated; darwin type-checks partially

- `make ebpf` needed the `dae_bpf_headers` submodule (`git submodule update --init --depth 1`),
  then succeeded with Homebrew `llvm@18` on PATH (clang, llvm-strip). The `bpf2go` outputs
  (`control/bpf_bpfel.go`, `trace/bpf_arm64_bpfel.go`) are present.
- dae is Linux-only. Run on darwin (the default `GOOS`), four packages (`cmd`, `component`,
  `component/outbound/dialer`, `control`) fail to type-check with 90 warnings, e.g.
  `undefined: unix.RTN_PROHIBIT`, `undefined: netlink.FAMILY_ALL`. That row is **degraded**.
- Run with `GOOS=linux` (raw linux outputs were overwritten by the darwin run in the same output dir), dae type-checks fully (0 type errors, 3 more modules, 78 more
  callables). The linux row is the representative one.

### cockroach: no protobuf generation; heavily degraded

- Bazel is not installed (`bazel`, `bazelisk` absent) and was not installed, so
  `./dev generate go` was not run. A plain checkout has 183 `.proto` and 0 `.pb.go`.
- Result: 62,908 type-error warnings across 633 packages (e.g. `undefined:
  tracingpb.StructuredRecord`, `undefined: build.Info`), plus cgo failures (`jemalloc/jemalloc.h`,
  `proj_api.h` not found). The analyzer still completed with all 5,953 modules and 88,765
  callables, but references into generated types are unresolved, so the call graph
  (156,068 in-project edges) is a lower bound. Counts and timings are real but not
  comparable to a fully generated tree.

### memos: no generation needed

`go build ./...` succeeds on the plain checkout; the single `go:generate` directive
(`markdown/parser/tag.go`, unicode tables) already has its output committed. `go generate`
was **not** run. 0 type errors.

## Reproducing

```
GOTOOLCHAIN=go1.27.3 go build -o /tmp/cango-eval ./cmd/codeanalyzer
scripts/eval_l3.sh /tmp/eval/cobra /tmp/eval/listmonk /tmp/eval/memos \
  /tmp/eval/nats-server /tmp/eval/openbao
GOOS=linux scripts/eval_l3.sh /tmp/eval/dae
scripts/eval_l3.sh /tmp/eval/cockroach
```

Clones are in `/tmp/eval` (`git clone --filter=blob:limit=2m`, then `git checkout <sha>`);
pinned commits are in the script header. Raw outputs and stderr logs are in `/tmp/eval-out`.
The "type errors" column in the script's own note counts `package ...` warnings on stderr.
